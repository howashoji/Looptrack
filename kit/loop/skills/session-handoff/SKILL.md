# セッションの引き継ぎの更新（session-handoff）

**目的は 1 つです**: このセッションがいま切れても次のセッションが「何が終わっていて・何が残っていて・次に何をするか」を
**読むだけで**再開できる状態にします。

セッションの終わりにだけ書く運用では、**終了処理を挟まずに切れたとき（文脈切れ・離脱・クラッシュ）に必ず失われます**。
実例: 4 件の作業を終えた直後の引き継ぎが 2 つ前の状態を指したままでした。完了済みのイシューが「待ちで中断」として残っていました。
次のセッションはその待ちから再開してしまいます。害は古いことそのものより**積極的に誤った方向へ導くこと**にあります。

## 発動のタイミング

- Stop hook `stop-handoff-freshness.sh` にやり直しを求められたとき（「引き継ぎが作業の完了に追いついていません」）
- 同じ Stop hook が**記録の消失**を知らせたとき（「更新の遅れではなく消失です」）。更新の遅れとは別の対応です。**この文脈に内容が残っているうちに書き戻してください**
- イシューを閉じた（close / Done / Canceled）直後と作業をコミットした直後（`post-work-complete-handoff-mark.sh` が促します）
- セッションを切り上げるとき・別の課題に移る前・コンテキストが残り少なくなったとき

## 手順（どのバックエンドでも同じ）

### 1. 事実を live 値で集める（記憶で書かない）

```bash
date '+%Y-%m-%d %H:%M'                                  # 引き継ぎに書く更新日時（推測しない）
git status --short; git log --oneline -5                # 作業ツリーと直近のコミット
looptrack issue list --status "In Progress"   # 進行中のイシュー
cat .claude/handoff-pending.d/* 2>/dev/null             # このセッションで完了したイベント（鮮度ガードのマーカー）
```

まだマージしていないもの・反映していないものがあればその事実も実測します（どのブランチに何コミット・どの環境に未反映か）。

### 2. 既存の引き継ぎを読む

下の「バックエンド」の節にある場所から読みます。

### 3. 引き継ぎを更新する（1 セッションは in-place・並行セッションは `append`）

**1 セッションなら最新の 1 件を書き換えます**。新しいファイルや記録を足して並べるとどれが最新か分からなくなります。
**並行セッションがいるなら、下の `looptrack handoff append` で自分の節を足します**。読んでから書き戻すとほかのセッションの節を消してしまいます
（節が増えたら `compact` で畳みます）。どちらの場合も次の項目を必ず入れてください:

| 項目 | 書き方 |
| -- | -- |
| `> 要約:` の行（ファイル版） | 1 行。セッション冒頭の一覧に出る。**省略しない** |
| 更新日時 | `YYYY-MM-DD HH:MM`（`date` の実値） |
| 現在地 | いま何がどこまでできているか（ブランチ・成果物のパス・未マージ / 未反映の実数） |
| **完了した作業** | イシューの ID と結果（Done / マージ済み 等） |
| **中断した作業** | **何をどこまでやり、次に何をすれば再開できるか**。ブロッカーがあれば理由と待ち先 |
| 未決事項 | 誰が・いつまでに・何を決めるか |
| 次に着手すべきこと | 優先順位つき |

**1500 字以内**に収めます。実装の細かな経過・変更したファイル・検証結果はイシューのコメントに書きます。ここには要点だけを置きます。
セッションの冒頭に入るのは `LOOPTRACK_LOOP_MEMORIES_MAX_CHARS`（既定 6000 字）までです。超えたら**末尾の節**と
**末尾から最も近い「現在地 / Where things stand / Current」の節**が入ります。**現在地は末尾に足すかその場で更新してください**
（先頭に古い現在地を残したままにしない）。
上限を超えて育ったら古い節を別ファイル（`archive-*.md`）に移すか、要点だけに畳みます。

**書き手の印を入れます（file バックエンド・既定）**: 自分が書いた節に hook が示す 1 行
（`<!-- looptrack:session <セッション ID> -->` の形）をそのまま入れてください。**引き継ぎは全セッションで同じ 1 ファイルです**。
更新時刻だけでは誰が書いたかが分からず、ほかのセッションの書き込みで自分のマーカーが畳まれてしまいます。
実物の行は作業の完了を検知したときとやり直しを求めるときに hook が出します（セッション ID を自分で調べる必要はありません）。
**印が 1 つも無い引き継ぎは、これまでどおり更新時刻で判定します**。まだ印を使っていないプロジェクトでは何も変わりません。
誰かが 1 度でも印を書いたファイルから判定が厳密になります。時刻だけの以前の判定に固定するなら `LOOPTRACK_LOOP_HANDOFF_WRITER=mtime` を使います。

**並行セッションがいるときは、直接編集せず `looptrack handoff append` で追記します**: 引き継ぎは全セッションで同じ 1 ファイルです。
読んでから全文を書き戻すとその間にほかのセッションが書いた節を丸ごと消してしまいます。消された側にはエラーが出ないので黙って失われます。
`append` は `O_APPEND` で 1 回だけ書くので同時に書いても混ざらず消えません。見出しの直後の印も `append` が入れます
（セッション ID を自分で調べる必要はありません）。全文を畳む（圧縮する）ときだけ `compact` を使ってください。`compact` には読んだ時点の
SHA-256 を渡します。その後にほかのセッションが書いていれば**何も書かずに拒否します**（読み直してからやり直してください）。

```bash
looptrack handoff append --title "<見出し>" - <<'EOF'
…本文…
EOF

shasum -a 256 <引き継ぎのパス>                        # 読んだ時点の SHA-256
looptrack handoff compact --sha <SHA-256> - <<'EOF'   # 全文の畳み直し（印を落とすなら --drop-marks）
## …
EOF
```

**1 セッションに戻るとき（印を使うのをやめる）**: `append` を使い始めたファイルは印を持つので鮮度ガードは厳密な判定に切り替わります。
**自分の印の無い更新は Stop でやり直しを求められます**（手で直しても「このセッションが書いた」とは数えられません）。並行セッションが去って
1 セッションに戻り、印を使うのをやめたいときは `compact --drop-marks` で印の行を落としてください
（印が 1 つも無いファイルはこれまでどおり更新時刻の判定に戻ります）。

### 4. 決定と教訓は別に置く

決定の理由や教訓を引き継ぎの本文に埋め込まないでください。次の更新で上書きされて消えます。

- 決定とその理由 → 決定の記録（ファイル版なら `decision-<topic>.md`）
- 再発防止の学び・落とし穴 → 注意の記録（ファイル版なら `caveat-<topic>.md`）
- 毎回守る作業の規則 → 記憶ではなく rules（プロジェクト側の rules）

どれも先頭に `# タイトル` と `> 要約: <1 行>` を置きます。引き継ぎからは名前で参照します。

### 5. マーカーを畳む

引き継ぎを更新すれば次の Stop で hook がマーカーを自動で消します。手で消すのは「引き継ぎが要らない」と判断したときだけにして、その理由を記録してください。

## バックエンド（プロジェクトで 1 つ選ぶ。`LOOPTRACK_LOOP_HANDOFF_BACKEND`）

### file（既定）— `.claude/memories/`

- 引き継ぎ: `.claude/memories/handoff.md` です（`LOOPTRACK_LOOP_HANDOFF_FILE` で変えられます）。決定・注意は同じディレクトリの `decision-*.md` / `caveat-*.md` に置きます。
- **パスは本体（メイン）の作業ツリーで解決します。** 作業ツリー（`git worktree add` で作った場所）の中から読み書きしても
  本体の `.claude/memories/` の 1 本を見ます。作業ツリー側に書くと誰にも読まれないまま `worktree prune` で消えるからです
  （`LOOPTRACK_LOOP_MEMORIES_DIR` / `LOOPTRACK_LOOP_HANDOFF_FILE` で明示したときはこれまでどおりそちらが優先です）。
  本体以外に取り残された引き継ぎが見つかったら Stop で 1 回だけ知らせます（止めはしません）。
- セッションの冒頭に `session-start-memories.sh` が引き継ぎと、ほかのファイルの `> 要約:` の一覧を注入します。
  引き継ぎは `LOOPTRACK_LOOP_MEMORIES_MAX_CHARS`（既定 6000 字）までです。超えたら
末尾の新しい節と末尾から最も近い「現在地 / Where things stand / Current」の節だけが入ります。
- 鮮度: **このセッションの印**（上の「書き手の印を入れます」）を持つ更新が完了イベントのマーカーより新しければ最新とみなします。
  同じディレクトリの別の `*.md` に書いたときも見ます。印が 1 つも無い引き継ぎと `LOOPTRACK_LOOP_HANDOFF_WRITER=mtime` のときは
  更新時刻だけで判定します（以前の動き）。
- 引き継ぎのファイルだけを変えたコミットは完了イベントとして数えません（規律どおりにコミットしてもガードが繰り返し反応しないように）。
- 消失: 前回あった `*.md` が無くなっていたら Stop で「消失」として知らせます（更新の遅れとは別の文言）。前回見た一覧の控えは
  `.claude/.looptrack-freshness/` と `<git のディレクトリ>/looptrack/` の 2 か所に持つので `.claude/` ごと消えても検知できます。
  **記録は版管理の下に置くのがいちばん確実です**。消えても戻せます。検知はあくまで気づくための最後の網です。

### auto-memory — Claude Code の auto-memory

- 引き継ぎ: `~/.claude/projects/<プロジェクトのパス>/memory/MEMORY.md` の「現在の作業」の行とそこから指す個別のファイルです
  （`LOOPTRACK_LOOP_HANDOFF_MEMORY_DIR` で変えられます）。`MEMORY.md` には 1 行のポインタだけを置き、本文は個別のファイルに書きます。
- 鮮度: `MEMORY.md` の更新時刻が完了イベントのマーカーより新しければ最新とみなします。**個別のファイルだけを直して `MEMORY.md` の該当行を
  放置しないでください**。次のセッションは `MEMORY.md` から読み始めます（「次にやること」に完了済みのものを残さない）。

### command — 記憶を DB 等に持つプロジェクト

- 引き継ぎの置き場（sqlite・MCP の記憶サーバなど）と鮮度の判定はプロジェクトが `LOOPTRACK_LOOP_HANDOFF_CHECK_CMD` に書きます
  （終了コード 0 = 最新 / 1 = 古い / それ以外 = 判定できない）。マーカーのパスは `LOOPTRACK_LOOP_HANDOFF_PENDING` で渡ります。
- 例: 引き継ぎの本文に `master=<短縮 sha>` を必ず書く決まりにします。判定コマンドで本流の到達点の sha と突き合わせます。
  記憶の同期だけのコミットは到達点から除きます。作業ブランチに乗っているだけで不一致にならないよう HEAD ではなく本流と比べてください。
- 更新は記憶のツールの「更新」で最新の 1 件を差し替えます（「追加」で並べません）。

## やってはいけないこと

- **引き継ぎを新しいファイル・新しい記録として積み重ねる**（最新が分からなくなります。1 セッションなら最新の 1 件をその場で書き換えます。
  並行セッションがいるときは `looptrack handoff append` で節を足して、増えたら `compact` で畳みます）
- **更新日時や `> 要約:` を書かない**（鮮度を判定できず一覧で中身も分かりません）
- **中断中の作業を「残り」とだけ書く**（次のセッションが再開の手順を探し直すことになります。**どこまでやったか・次の 1 手**まで書きます）
- **「完了」と書いてまだマージ・反映していないことを書き忘れる**（反映の状況は必ず書きます）
- **決定の理由や教訓を引き継ぎに埋め込む**（上書きで消えます。決定・注意の記録に分けます）
- **実装の細かな経過を書く**（イシューのコメントに書きます。引き継ぎには要点だけを置きます）
