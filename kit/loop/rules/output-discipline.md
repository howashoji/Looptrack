# 出力規律（ツール呼び出しの書式・言行一致）

> kit/loop の rules です。毎セッション守ってください。3 層の hook で常に目に入るようにし、違反を検知します。
> SessionStart `session-start-rules.sh` が下の「毎セッションの要点」を、UserPromptSubmit `user-prompt-rules.sh`
> が「毎ターンの要点」を注入します。Stop `stop-tool-markup-guard.sh` は素の markup が残った返答のやり直しを求めます。
> 言行一致を語彙で検知する Stop hook は廃止しました。誤検知が多く、誤ったやり直しの要求で利用者の判断を飛ばした例もあったからです。
> 言行一致は下の規則として守ります。イシューの更新漏れは core の鮮度ガードが状態から検知します。

## 毎セッションの要点
<!-- looptrack:inject session claude-code -->

ツール呼び出しの書式（毎セッション厳守）:
1. ツール呼び出しは**メッセージの冒頭**に単独で置きます。説明文をツール呼び出しの前に書かないでください。散文からツール呼び出しへ移るところで antml: 名前空間が抜け落ちます。
2. 説明や前置きはツール呼び出しの**後ろ**か別のターンに回します。独立した複数の呼び出しは 1 メッセージにまとめて冒頭に置きます。
3. malformed / 未パースの警告を受けたら、**前置きなしで**ツール呼び出しだけをすぐ送り直してください。説明や謝罪を先に書くと再発します。
4. ツール呼び出しは `antml:invoke` / `antml:parameter` で開きます。素の invoke / parameter や先頭の count / court などが混ざると no-op として拒否され、実行されません。
5. ブロッカーが無いなら、行動の宣言でターンを閉じません。次の行動そのもの（ツール呼び出し）を取ってください。

## 毎ターンの要点
<!-- looptrack:inject prompt claude-code -->

[出力規律] ツール呼び出しはメッセージの冒頭に置きます。説明文をツール呼び出しの前に書かないでください（散文からツール呼び出しへ移るところで書式が崩れます）。malformed / 未パースの警告を受けたら前置きなしでツール呼び出しだけをすぐ送り直します。ブロッカーが無いなら宣言で閉じず、次の行動を取ります。

## 1. ツール呼び出しの書式（最重要）

**根本原因（実証済み）**: ツール呼び出しの書式ミスは、例外なく「**散文を書いた直後にツール呼び出し**」へ移るところで起きます。
先頭の `antml:` 名前空間が抜け、harness が malformed として拒否し、no-op で作業が止まります。
メッセージをツール呼び出しから直接始めた場合は毎回成功しました。
デコーダは変えられないので、**引き金になる条件（prose-before-tool）を規律でなくします**。

### 厳守事項
1. **ツール呼び出しはメッセージの冒頭に単独で置きます**。説明文をツール呼び出しの前に書かないでください。
2. 説明や前置きはツール呼び出しの**後ろ**か別のターンに回します。独立した複数の呼び出しは 1 メッセージにまとめて冒頭に置きます。
3. **malformed / 未パースの警告を受けたら、前置きなしでツール呼び出しだけをすぐ送り直します**。説明や謝罪を先に書くと再発します。
4. ツール呼び出しは `antml:invoke` / `antml:parameter` で開きます。素の `invoke` / `parameter` タグや先頭の `count` / `court` などが混ざると
   no-op として拒否されます。実行されないのでデータは壊れませんが、作業は止まります。

### 3 層の enforcement
- **SessionStart** `session-start-rules.sh`: このファイルの「毎セッションの要点」をセッションの冒頭で注入します。最初のツール呼び出しより前から目に入ります。
- **UserPromptSubmit** `user-prompt-rules.sh`: 「毎ターンの要点」を毎ターン注入します。
- **Stop** `stop-tool-markup-guard.sh`: 返答のテキストに未パースの markup が残っていたら Stop のやり直しを求め、正しい書式ですぐ送り直すよう促します。

## 2. 言行一致

- 「続けます」「進めます」「着手します」のような**これからの行動の宣言には、同じターンのツール呼び出しを付けます**。
  確認の質問やブロッカーの報告でない限り、宣言とツール呼び出しをそろえてください。
- 作業の途中（in_progress）で、ツール呼び出しの無いままターンを閉じないでください。
- **ブロッカーが無いなら、宣言でターンを閉じません。次の行動そのものを取ります。**
  「次は〇〇をマージして検証に入ります。」と書いて閉じると、CI 待ちなどのブロッカーが既に解けていても止まったままになります。
  利用者が次に話しかけるまで何時間でも動きません（実例: CI は既に緑だったのに約 14 時間止まっていました）。
  宣言だけのターンは、利用者からは動いているように見えます。**遅いことよりも、進んでいるように見せて待たせることのほうが害**です。
- **依存待ちはブロックではありません**。「〜したら」「〜次第」「完了を待って」のように本当に外部の完了を待っている文なら、やり直しは求めません。
  そのときは何を・誰を待っているかを書いてターンを閉じます。待つ相手が利用者なら質問として書いてください。
  誤検知が続くとガードはいつも迂回されるようになり、意味を失います。
- 利用者の判断を待つ分岐は、質問のツール（Claude Code の `AskUserQuestion` など）で示しましょう。宣言と行動がそろいます。
