# 実装イテレーション規律

> kit/loop の rules です。実装とテストを自動で進める前提で、2 つの規律を置きます。見つけた問題は必ずイシューにすること。問題を抱えたまま次の実装を積み上げないこと。
> ペア: SessionStart `session-start-iteration`（未解決の bug の注入）/
> `looptrack gates`（ゲートの実行）/ skill `/iterate`（手順）。
> プロジェクト側の rules に固有の実装規律（ワークフロー・テスト階層の定義・コミット規約）があれば、食い違ったときはそちらを優先します。

## 要点
<!-- looptrack:inject session codex copilot -->

- 1 イテレーションは 1 実装イシューです。実装 → ゲート（`looptrack gates`。段が 1 つでも欠けたら緑と言いません）→ 問題ゼロの確認 → close（実証のコメント）→ 次へ、と進めます。
- 見つけた問題はその場で `--type bug` で起票します（再現 / 期待 / 実際 / 検出した段階）。bug を抱えたまま新しい実装を積み上げず、直せるものから直してください。
- bug の解決は、修正・同じ問題を検出するテストの追加・ゲートの全緑・close コメントへの実出力の引用がそろったときです。

## 1. イテレーションの定義

1 イテレーションは 1 実装イシューです。次の順で進め、**段を飛ばさないでください**:

```
実装 → ゲート（build → lint → test …）→ 問題ゼロの確認 → close（実証コメント）→ 次の実装へ
```

- ゲートは `gates.sh` で実行します。`make -C <ディレクトリ> <段>` のラッパで、fail-fast でログも残します。
  段とディレクトリはプロジェクトが決めます（引数か環境変数 `LOOPTRACK_LOOP_GATES_STAGES` / `LOOPTRACK_LOOP_GATES_DIR`）。
  手でテストを実行した場合も、close の前には必ず `gates.sh` で全段を通してください。
- **段が 1 つでも欠けていたら緑と報告しません**。Makefile に無い段やレシピの無い段は失敗として扱います。何も実行せずに PASS する「偽緑」を防ぐためです。

## 2. 問題のイシュー化（発見 = 起票）

ここでいう「問題」は、ゲートの失敗・テストの失敗・設計との食い違い・想定外の挙動・実装中に見つけた既存コードの欠陥です。

- 見つけた**その場で** `--type bug` で起票します。対象の要件のイシューへの `--traces` を付け、本文には
  **再現手順 / 期待（要件・設計の該当箇所）/ 実際（実ログの引用）/ 検出した段階** を書きます。
- 会話・TODO コメント・頭の中に問題を抱えたまま先へ進まないでください。起票しない問題は無いのと同じに扱われます。
  その会話が終われば誰にも見つからず、覚えている人がいる間しか残りません。
- 設計と食い違う場合は bug ではなく、設計の見直しとして決定の記録を付けて利用者に諮ります。迷ったら bug で起票し、本文に「設計確認要」と書いてください。
- **未クローズの `type: bug`（`looptrack issue list --type bug`）を抱えたまま、新しい実装を積み上げません。** SessionStart が件数と一覧を出します。
  着手の前にそれを見て、直せるものから直しましょう。残すなら、なぜ今直さないかをイシューに書きます。
- bug の解決には、修正・検出した段階のテストの追加・ゲートの全緑・close コメントへの実出力の引用が要ります。テストを足すのは、同じ問題を二度と手で見つけないためです。

## 3. 自動進行の原則

- 「実装 → ゲート → bug 起票 → 修正 → close → 次の実装」は、利用者に 1 つずつ確かめずに続けてかまいません。
  ただし親イシュー（エピック）の範囲の中に限ります。範囲や設計を変える必要が出たときだけ、止めて利用者に諮ってください。
- 受け入れ条件は自動テストにします。目視の確認のように自動化できない検証は、何をどう確かめたかをイシューのコメントに残します。
- コミットはイシュー単位です。イテレーションが終わったら引き継ぎを更新します（skill `session-handoff`）。

## 4. 本ファイルの運用

- ゲートの実コマンド（段・ディレクトリ）はプロジェクト側で決め、Makefile と `LOOPTRACK_LOOP_GATES_*` に置きます。この文書には複製しません。
- 運用して得た学びは、プロジェクト側の rules か記憶（引き継ぎのバックエンド）に移して残してください。
